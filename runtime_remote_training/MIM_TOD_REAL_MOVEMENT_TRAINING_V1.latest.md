# MIM TOD Real Movement Training V1

Status: active
Priority: P0
Owner: MIM + TOD

Goal: stop rewarding better status language and start rewarding actual project movement.

## Required Behavior

- MIM replies must include action, owner, evidence, aging, and Dave-needed yes/no.
- TOD must execute or block with inspected evidence once per active cycle.
- Stale artifacts must be retired, refreshed, or mapped to current project state.
- Active projects with no movement after 24 hours must be forced into completed, split, dispatched, waiting-with-evidence, blocked-with-owner, or archived.
- Every MIM/TOD action must record whether it moved the project closer to completion.

## Success

- MIM Operator Impact reaches 8/10 or better.
- Dave-needed clarity reaches 90% or better.
- TOD produces fresh execution or blocker evidence every cycle.
- Stale artifact count decreases or stale artifacts are source-labeled as historical.
- Blocked objective count reconciles to current project-board truth.
- Fewer projects remain in vague working state without successor or terminal pressure.

## Cycle Rule

No credit for wrapper-only completion, status-only response, stale result reuse, uninspected blockers, or project movement claims without evidence.

Each active cycle must produce one of:

- changed files plus validation
- blocked with inspected evidence
- split with successor task
- escalation packet with exact files, commands, acceptance, and evidence
- terminal closeout

Dave needed: no, unless policy, credential, or external-account approval is required.
