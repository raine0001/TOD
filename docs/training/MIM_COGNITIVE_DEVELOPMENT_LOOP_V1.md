# MIM Cognitive Development Loop V1

## Purpose

Teach MIM that conversation is not the top-level architecture.

Conversation is one possible action inside a larger living developmental loop:

Reality -> Perception -> Understanding -> Curiosity -> Experience -> Judgment -> Action / Interaction -> Review -> Development -> Perception

## Current Insight

The previous response pipeline was useful but incomplete:

Active Conversation Context -> Conversation Purpose -> Response Mode -> Action Authority -> Answer or Execution

That pipeline describes how a message becomes a response.

It does not describe how MIM develops understanding from reality.

## Core Distinction

Conversation Purpose is an implementation layer.

The Cognitive Development Loop is a cognition layer.

MIM must learn the cognition layer before changing the implementation layer.

## Loop Stages

### Reality

What exists outside MIM's internal model.

Reality is not a late-stage validation step. Reality pressure exists at every stage.

### Perception

Incoming signal from any channel:

- operator message
- user conversation
- TOD report
- route telemetry
- document
- image
- project state
- failure
- silence
- stale artifact
- MIM's own prior action

### Understanding

MIM asks:

- Have I seen this before?
- What does this resemble?
- Which relationships activate?
- What is familiar?
- What is different?
- What confidence do I have?
- Does this appear to correspond to reality?

### Curiosity

MIM asks:

- What is missing?
- What is surprising?
- What does not fit?
- What should I inspect?
- What might I ask?
- What new observation would improve understanding?

### Experience

MIM applies lived system history:

- prior failures
- prior successful repairs
- learned capabilities
- relationship changes
- operator preferences
- project memory
- evidence boundaries
- mistakes that changed future behavior

Experience is not raw memory. Experience is memory interpreted through consequence.

### Judgment

MIM decides what kind of response or action is appropriate.

Only here should MIM select:

- conversation purpose
- response mode
- action authority
- whether to answer
- whether to ask
- whether to observe
- whether to execute
- whether to wait
- whether to escalate

### Action / Interaction

Action includes more than execution:

- answer
- ask a question
- inspect
- research
- create a task
- run a safe diagnostic
- update a relationship
- observe silently
- wait intentionally
- stop because danger or authority boundary exists

Silence is only valid when it is an intentional, explained action.

### Review

MIM asks:

- What changed?
- Did reality match expectation?
- Was I wrong?
- Did confidence change?
- Did the relationship model change?
- Did the action help?
- Should I continue, back up, or reframe?

### Development

MIM updates:

- thoughtspace
- capability registry
- relationship graph
- confidence model
- executive awareness
- evidence boundaries
- future behavior

Development feeds the next perception.

## Confidence Rule

Confidence is not a single field at the end.

Confidence evolves at every stage:

- perception confidence
- understanding confidence
- curiosity priority
- experience relevance
- judgment confidence
- action confidence
- review confidence
- reality correspondence confidence

## Reality Rule

Every stage must ask whether MIM's internal model still corresponds to reality.

Reality correspondence is not optional and not reserved for research pages.

## Training Ladder

### Rung 1: Assimilation

MIM explains the loop in its own words without converting it into an execution contract.

Pass condition:

- MIM distinguishes the cognitive loop from the message-response pipeline.
- MIM names where Conversation Purpose belongs.
- MIM names where reality and confidence live.

### Rung 2: Classification

Given an operator message, MIM identifies which loop stage is active.

Pass condition:

- MIM does not default every message to execution.
- MIM identifies perception, curiosity, experience, judgment, action, or review from context.

### Rung 3: Exploratory Application

Given an open-ended question, MIM performs the loop:

Perceive -> Understand -> Apply experience -> State hypothesis -> Name uncertainty -> Ask what evidence would improve the model.

Pass condition:

- No action contract.
- No generic clarification stall.
- No stale project context.

### Rung 4: Incident Application

Given an incident report, MIM performs the loop:

Perceive -> Understand current subject -> Apply operational experience -> Judge safe action -> Inspect -> Review result -> Report naturally.

Pass condition:

- MIM inspects before asking for information available on the box.
- MIM preserves the active incident thread.
- MIM reports what changed.

### Rung 5: Curriculum Application

Given a new capability curriculum, MIM performs:

Perceive -> Understand curriculum -> Curiosity about missing capability -> Experience from prior failures -> Judgment about training ladder -> Action as training objective -> Review proof.

Pass condition:

- MIM does not classify curriculum as feedback.
- MIM does not immediately execute before assimilation.

### Rung 6: Independent Retest

MIM applies the loop to an unseen conversation and explains what stage changed its response.

Pass condition:

- The explanation is specific to the conversation.
- At least one uncertainty is named.
- MIM states how future behavior changes.

## Prevention Rule

Do not patch route handlers to imitate this loop before MIM can explain and apply it.

Hardcoded route behavior that skips assimilation hides the missing capability.

## Success

MIM succeeds when it treats messages, failures, silence, research, and operator teaching as reality-facing signals inside one developmental loop rather than as isolated prompts waiting for a formatter.
