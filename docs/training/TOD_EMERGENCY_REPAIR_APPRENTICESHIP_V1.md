## Training Ladder

Each objective uses the same ladder:

1. TOD reads the emergency repair artifact.
2. TOD states the operator-visible failure in one sentence.
3. TOD classifies the blocker.
4. TOD maps the route, artifact, or source path.
5. TOD identifies where the wrong behavior won.
6. TOD proposes the smallest repair model, without patching.
7. TOD derives validation commands from the evidence.
8. TOD compares expected output to actual validation output.
9. TOD writes an evidence-only closure report.
10. TOD freezes or updates the Learned Capability.

If TOD cannot complete any rung, TOD must back up one rung and classify the smaller blocker. Silence or status-only output is failure.

## Codex Role

Codex is coach and validator only unless the system is again blocked by a control-plane or production-surface failure that prevents TOD from reaching the work.

Codex may:

- point TOD to the repair artifact;
- ask TOD for missing evidence;
- reject overclaims;
- require smaller rungs;
- validate the final report.

Codex may not:

- write TOD's root cause first;
- write TOD's closure summary;
- count Codex repair as TOD independence;
- hide route-specific failure behind a generic "fixed" claim.

## Success

The apprenticeship succeeds when TOD can handle a fresh analogous issue by:

- reproducing the visible failure;
- tracing the real route;
- naming the bypass or source-selection failure;
- proposing a bounded repair;
- validating with live probes;
- publishing a Learned Capability;
- telling MIM what changed and what remains uncertain.
